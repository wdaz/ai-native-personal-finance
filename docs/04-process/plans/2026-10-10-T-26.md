  page's tools (the WM-Q3 (a) case). Both client-navigation tests in `webmcp.spec.ts` poll the names instead.
- **F5. `getTools()` lists the tools in name order**, not registration order; the E2E compares sorted names.
- **F6. The phone keyboard walkthrough ran on `/pots`** because it was a placeholder; it now walks the page's
  controls too (2.10's order: "Add New Pot", "Log out", each card's "…", "Add Money", "Withdraw").

## Decisions taken in the plan (the spec leaves them to the build)

- **D1. One write function in `PotsBoard`**: `slot.trackWrite` + `apiSend` + `writeAnswer`, then
  `router.refresh()` inside `startTransition`, with `aria-busy` on the grid while it is pending (2.1, 2.8). The
  form and the money modal claim the modal slot when they open, outside any state updater.
- **D2. The bars are inline SVG `rect`s** (ADR-0006: no `style` attribute): the width and `x` are percentage
  presentation attributes; `rx`, the transform and the transitions come from the CSS modules.
- **D3. The preview's corners (2.6, §25f)**: the staying segment is a square `rect` (the track's radius and overflow
  round its left end); the moving segment is a rounded `rect` shifted by `--spacing-25`, with a square copy clipped
  to a 4 px strip at its left edge, so its inner edge is square and its outer end rounded.
- **D4. The tool inputs are the routes' schemas with the `id` added**; `delete_pot` runs the bus's
  `runDeleteTool("pot")`; `PotsTools` wraps the four write tools with `router.refresh()` after a success, memoized.
- **D5. Amounts wrap at their commas** (`AmountText`, a `<wbr>` after each), so "Target of $999,999,999.99" fits
  320 px whole on its own line (§18e).
- **D6. `pots.md` §4.7–§4.9 are computed** (`potWidths`, `descriptionLengths` with the tools passed in, since
  ADR-0002 keeps scripts out of `src/webmcp`, and `contrastRatio` over `tokens.css`), and the figures test holds the
  spec's text to them.
- **D7. E2E data through the API or the database** (NFR-T3): the fifteen pots and the zero balance through the API;
  the 429 by filling `WriteAttempt` for the address the server recorded for the test's first write; the threshold
  reset by inserting one row past `RESET_ROW_THRESHOLD`, since a money move adds no row.
