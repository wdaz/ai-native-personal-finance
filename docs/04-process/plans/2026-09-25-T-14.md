**Goal:** the app runs publicly at a stable HTTPS URL on Vercel (NFR-D4), in `fra1` next to its
Neon database in Frankfurt, seeded and reset by the daily cron (NFR-D5, US-37); every pull request
gets a preview on its own Neon branch; Lighthouse measures Overview and Transactions (NFR-P1/P2);
and every hand-off in T-14's row is checked on the deployment — TD-14 first, on this task's own
preview, before the merge that deploys production.

**Architecture:** four phases, ordered by one hard fact — a merge to `main` is a production deploy
(ADR-0007) — and one invariant: **the production database holds no seed data until T-14 has
merged** (F4). (A) Repository changes on `task/T-14-deploy`, local only: migrations through Neon's
direct URL with the TD-10 guard reading it (Task 1), `vercel.json` (Task 2), the Lighthouse
workflow (Task 3), the deploy runbook (Task 4). (B) Platform setup, mostly the owner's: the Vercel
project, the Neon-managed Vercel integration, environment variables, Deployment Protection's bypass
secret (Task 5). (C) The pull request's preview: build-log checks, the preview seeded, TD-14, the
proxy on Vercel, TD-17, TD-3, the host's TLS items, the `APP_ENV=test` refusal; then the records and
an Opus review; the owner merges (Tasks 6–7). (D) Production: migrations in its build, the first
seed, smoke checks, the cron, the origin-trial token, Lighthouse, and a close-out pull request
(Task 8).

## Review Focus

The inputs and conditions the row implies but no existing test exercises, most likely first. Each
has its check in the task named.

1. **`npm run db:reset` with a local `DATABASE_URL` and a remote `DATABASE_URL_UNPOOLED`** — the
   shape a `vercel env pull` or `neon env pull` leaves behind. Once migrations use the direct URL
   (Task 1), a guard that reads only `DATABASE_URL` would let `migrate deploy` run against the
   remote database. Task 1, test "npm run db:reset refuses a remote DATABASE_URL_UNPOOLED …".
2. **TD-14 reading "safe" for the wrong reason.** A preview branch starts as a copy of `production`
   (F3), which is empty before the merge; a proxy-skipped `/overview.rsc` would then answer 500
   ("No Balance row") and look like no leak. Task 6 seeds the preview first, uses `X-Request-Id`
   (set by the proxy on every response it handles, `tests/api/proxy.spec.ts`) to tell whether the
   proxy ran whatever the status, and runs a positive control with a real session.
3. **A preview's secret opening production.** Shared `RESET_SECRET` or `SESSION_SECRET` values
   would let anyone who can reach a preview reset production or mint its cookies. Task 5 sets
   distinct values per scope; Task 8 checks the preview's `RESET_SECRET` gets 401 on production.
4. **Production reachable with data before TD-14 passes.** The first deployment of a new Vercel
   project is always production (F4), and installing the integration may redeploy it. Task 5 checks
   the deployments list after the integration and that production's `/api/meta` still has no
   `ResetLog` row.
5. **The cron failing silently.** Hobby runs it once within the hour, never retries and never
   follows a redirect (F11). Task 8 calls `GET /api/admin/reset` with `CRON_SECRET` by hand (200,
   no redirect) and reads the first scheduled run's log the next day.

## Findings — verified 2026-09-25

Sources were read on 2026-09-25 unless a date is given. "Research" = the subagent reports named in
the plan-gate note; the agent re-read the Vercel Node-versions and region pages itself.

- **F1 Node.** Vercel builds and functions run 24.x (default), 22.x, 20.x
  (vercel.com/docs/functions/runtimes/node-js/node-js-versions); the repository is on 24 since
  PR #57 (`.nvmrc`, `engines.node` `24.x`, `tests/unit/node-version.test.ts`). Node 24.20.0+
  bundles npm 11.19.0 (nodejs.org/dist/index.json); the npm of Vercel's image is not stated —
  Task 6 reads it from the build log.
- **F2 Neon project** (Neon CLI, read-only): `solitary-truth-56663324`, "Personal finance", org
  `org-withered-frost-82646416`, `aws-eu-central-1`, Postgres 18, one branch `production`
  (default, not protected). Neon Auth, object storage, functions and AI gateway are off. The Neon
  MCP server is read-only and pinned to this project.
- **F3 Neon-managed Vercel integration** (research; neon.com/docs/guides/neon-managed-vercel-integration,
  /vercel-overview, /vercel-branch-cleanup): it connects an *existing* Neon project to a Vercel
  project that is **already linked to Git**; it **fails if `DATABASE_URL`, `PGHOST`, `PGUSER`,
  `PGDATABASE` or `PGPASSWORD` already exist** in the Vercel project; it sets `DATABASE_URL`
  (pooled), `DATABASE_URL_UNPOOLED` (direct) and legacy `POSTGRES_*`/`PG*` for Production and
  Development, and injects Preview values per deployment for a branch `preview/<git-branch>`,
  created from the parent "with the parent's full dataset"; it runs no migration (its docs suggest
  the build command runs `prisma migrate deploy`); "Automatically delete obsolete Neon branches" is
  opt-in and "runs the next time a preview deployment is created"; an optional `vercel-dev` branch
  backs Development. The Vercel-managed native integration creates its own Neon organisation and
  cannot attach this project. Hobby support: not stated.
- **F4 The first deployment is production.** "The first deployment of a new project is always a
  production deployment … even when you … deploy from a branch that is not your production branch"
  (vercel.com/docs/deployments/environments). Creating the project by CLI would make an unmerged
  branch production; importing `main` in the dashboard is the least-bad first deploy — it has no
  database yet, and after the integration its database is empty. Hence the invariant above.
  Whether installing the integration redeploys production: not stated (Task 5 checks).
- **F5 Migrations need the direct URL.** `prisma.config.ts` passes `process.env.DATABASE_URL` to
  the CLI (line 34); on Vercel that is Neon's pooled URL. Prisma 7 removed `directUrl`; Neon: schema
  migrations "need a direct connection", and its pooler (PgBouncer, transaction mode) does not
  support session-level advisory locks (neon.com/docs/connect/connection-pooling). The app's own
  reset takes `pg_advisory_xact_lock` (`src/server/reset.ts:39`), a transaction-level lock the
  pooler's list does not exclude — inference: it works; Task 6's preview seed exercises it.
- **F6 TD-14 locally.** Next 16.3.5 appends `(\.json|\.rsc|\.segments/.+\.segment\.rsc)?` to every
  matcher; with `proxy.ts`'s `/((?!_next/static|_next/image|favicon\.ico|.*\..*).*)` the compiled
  matcher gives `/overview` true, `/overview.rsc` false, `/overview.segments/_tree.segment.rsc`
  false (research, local `node`). Whether Vercel then serves the page's payload without the proxy
  is not stated anywhere; Next's advisory GHSA-267c-6grr-h53f is the same class ("`.rsc` and
  segment-prefetch URLs can resolve to the same page without being matched by the intended
  middleware rule"). `app/(app)/overview/page.tsx` and its layout do not check the session
  themselves (TD-14).
- **F7 X-Forwarded-For.** "we currently overwrite the `X-Forwarded-For` header and do not forward
  external IPs. This restriction is in place to prevent IP spoofing"; `x-real-ip` and
  `x-vercel-forwarded-for` are the same value (vercel.com/docs/headers/request-headers). This is
  the citation TD-17 asks for.
- **F8 TLS and HSTS.** `.vercel.app` and its subdomains send
  `Strict-Transport-Security: max-age=63072000; includeSubDomains; preload` and are preloaded;
  HTTPS redirection "can't be disabled"; TLS 1.2 and 1.3 (vercel.com/docs/cdn-security/encryption).
- **F9 TD-3 on the CDN.** Vercel caches a Function response that sends `s-maxage`
  (vercel.com/docs/caching/cdn-cache); a nonce added at render "prevents the completed document from
  being reused by a CDN" only when the page is dynamic (vercel.com/kb/guide/csp-nonces-with-cdn-cache).
  Inference: `/_global-error` (prerendered, `s-maxage=31536000`) is cached and replayed; its inline
  tags carry no nonce anyway (TD-3), so the replay changes what the CSP *header* says, not whether
  the page works. Task 6 measures `x-vercel-cache` on two requests.
- **F10 Deployment Protection.** Default for new projects: Standard — Vercel Authentication on
  every deployment URL except production domains; on Hobby, Vercel Authentication and
  "Protection Bypass for Automation" are included; the bypass is a header
  `x-vercel-protection-bypass: <secret>` (also `VERCEL_AUTOMATION_BYPASS_SECRET` in the
  deployment) (vercel.com/docs/deployment-protection and its usage-and-pricing page).
- **F11 Cron.** Production only; `GET` with `Authorization: Bearer <CRON_SECRET>`; once a day,
  anywhere in the hour; failed runs are not retried; redirects are not followed
  (vercel.com/docs/cron-jobs, /manage-cron-jobs, /usage-and-pricing). `proxy.ts` lets
  `/api/admin/reset` through without a session (SPEC-auth §2.10, `tests/api/proxy.spec.ts`
  "only POST /api/admin/reset is secret-protected").
- **F12 Install and build.** With a lockfile Vercel runs `npm install`; `installCommand` overrides it
  (vercel.com/docs/package-managers, /project-configuration/vercel-json). Whether a committed
  `.npmrc` is honoured: not stated — Task 6 reads the build log for `Unknown project config`. The
  `prepare` script is safe without `.git` (`scripts/install-git-hooks.sh`); `postinstall` runs
  `prisma generate`.
- **F13 Local files the platform CLIs write.** `vercel env pull` → `.env.local` by default (CLI
  source); `neon link --branch …` also runs `env pull` → `.env` if present, else `.env.local`
  (neon CLI README); `.neon` is **not** in `.gitignore`; `.env*` and `/.vercel` are.
- **F14 Origin trial.** Registered at developer.chrome.com/origintrials (WebMCP trial, Chrome
  149–156); a token is bound to one origin by default, and subdomain tokens are not issued for
  Public-Suffix-List origins — `vercel.app` is one — so the token covers exactly
  `https://<project>.vercel.app` (developer.chrome.com/docs/web-platform/origin-trials, research).
  Exact expiry: not stated on Chrome's pages.
- **F15 OWASP items T-13d could not test without a host** (from
  `prompts/2026-09-25-T-13d/*.md`): TRAN-01–06 (TLS, certificate, HTTP→HTTPS, HTTPS everywhere,
  `Secure` cookie over HTTPS, HSTS), INFO-04 (search-engine discovery; there is no `robots.txt`),
  INFO-12/INFO-13 (deployment and host inventory), DOS-03 (host limits), BIZ-02 (the reset's log
  line), and CONF-04/AUTHZ-02/AUTHZ-05/AUTHN-16/SESS-11, which all reduce to TD-14. VAL-02, VAL-19
  and VAL-31 wait for Release 2's write paths.
- **F16 Lighthouse.** `@lhci/cli` takes page headers as `collect.settings.extraHeaders` (a JSON
  string); Vercel emits `deployment_status` (the environment names "Production"/"Preview" are not
  stated); under Standard protection the per-deployment URL of a production deployment is
  restricted, the production domain is not (research). No `lighthouserc*` exists yet.
- **F17 Environment inventory** (`.env.example`, `src/server/env.ts`, `src/server/session.ts`,
  `next.config.ts`): `SESSION_SECRET` (≥ 32 characters or every request throws), `DEMO_EMAIL`,
  `DEMO_PASSWORD_HASH` (a raw `$2[aby]$NN$…` bcrypt hash — **not** `\$`-escaped in Vercel, README
  "Demo credentials"), `DEMO_PASSWORD_DISPLAY` (public, NFR-S1), `RESET_SECRET`, `CRON_SECRET`
  (production; ≥ 16 random characters per backlog T-08), `WEBMCP_MODE` (`polyfill`; inlined at

/**
 * TD-10, T-14: the variables a run may reach a database through. `DATABASE_URL` is the
 * application's (Neon's pooled connection on Vercel); `DATABASE_URL_UNPOOLED` is the direct one
 * the Neon-managed Vercel integration sets beside it, which Prisma's CLI uses for migrations
 * (`migrationDatabaseUrl`). A run that resets, seeds or migrates refuses if either is not local —
 * after a `vercel env pull` the pair can disagree.
 */
const DATABASE_URL_NAMES = ["DATABASE_URL", "DATABASE_URL_UNPOOLED"] as const;

/**
 * T-14: the URL Prisma's CLI connects through (prisma.config.ts). Schema migrations need Neon's
 * direct connection — its pooler runs PgBouncer in transaction mode, which has no session-level
 * advisory locks (neon.com/docs/connect/connection-pooling, read 2026-09-25). Locally and in CI only
 * `DATABASE_URL` exists. Unset and empty both fall back; neither set is `undefined`, and Prisma
 * names the missing datasource.
 */
export function migrationDatabaseUrl(env: EnvVars): string | undefined {
  return env.DATABASE_URL_UNPOOLED || env.DATABASE_URL || undefined;
}

export function localDatabaseRefusal(env: EnvVars): string | null {
  const refused = DATABASE_URL_NAMES.some((name) => {
    const url = env[name];
    return url !== undefined && url !== "" && !isLocalDatabaseUrl(url);
  });
  if (!refused) return null;

    "(localhost, 127.0.0.1 or [::1]) or is not a plain postgres:// or postgresql:// URL (no " +

    "or migrates that database. Point both at the local database from compose.yaml (README, Run " +
    "locally) — TD-10"

}
