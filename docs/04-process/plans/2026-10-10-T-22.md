## Decisions taken in the plan (the spec leaves them to the build)

- **D1. One join of the dialog and the bus, in `app/`.** 2.3 says the page joins the dialog to the bus, since
  `src/ui` may not import `src/webmcp`. Both pages need the same join, and §7 tests it, so it is written once as a
  hook in `app/(app)/_write/use-delete-flow.ts` (a private folder: no route): the page passes its kind, its
  records and its delete function; the hook subscribes with `onDeleteRequest`, opens the dialog for a person's
  "Delete" or a tool's request, and resolves the tool from the request's answer (2.3 item 4), even after an
  unmount. T-24 and T-26 use it.
- **D2. `writeAnswer` in `src/shared/write-feedback.ts`.** One pure function turns an `ApiOutcome` into what
  `write-path.md` §3 shows: `ok`, `validation` (with `issues`), `gone` (404), `reset` (409), `session` (401), or
  `failed` with the message (429 `COPY.writeRateLimited`; 403, 415, 500 and a bad body "Something went wrong. Try
  again"; no response "Can't reach the server…" — the existing `COPY` entries §3 names) and its tool code
  (`write-path.md` 2.11 (4)). The dialog, the footer and the bus read it.
- **D3. `Menu`'s options for `SelectField`** (§6, H13 (1)): `variant: "field"` (the label above, `Field`'s 47 px
  box, no icon-only trigger, a "Already used" option grey-500 with no hover), `renderValue` and `renderOption` (the
  swatch, "Already used", the check), `pointerFocus` (2.6's two pointer rules), `invalid` and `describedBy`, and
  `onFieldBlur` (focus leaving the field as a whole). For every use, the Escape it handles stops propagating;
  in the field variant, with no value, the trigger is named by its label alone (the toolbar keeps its "Sort by: "). The Transactions and Recurring Bills menus pass none of the
  new options and keep their behaviour.
- **D4. `Modal` is a `div` with `role="dialog"`** in a portal on `document.body` (§8: the native `<dialog>` is
  out of scope). The layer is the backdrop (`var(--color-backdrop)`, `overflow-y: auto`, `overscroll-behavior:
  contain`); a press and release on the layer itself is a backdrop click. Focus return takes a function, read when
  the modal closes, so a page can name `<main>` at that moment (2.2).
- **D5. A reload is one function** (`reloadPage` in `src/ui/reload.ts`), so the dialog and the footer can be tested
  without jsdom's missing `location.reload`.
- **D6. The tokens** (H13 (3)): a new "Modals and forms (v1.6)" table (`--modal-max-width`, `--action-menu-width`,
  `--field-menu-max-height`, `--duration-modal`) and `--color-backdrop` as a backticked value, and an "Opacity"
  table with `--opacity-unavailable`. `tests/unit/scaffold.test.ts` reads every backticked value (shadow and
  backdrop) and the opacity table.
- **D7. The copy** (H13 (2)): one appendix table, "R2 additions … SPEC-ui-kit, added by T-22", and the same
  entries in `COPY`: `close`, `deleteTitle` ("Delete ‘{name}’?"), `confirmDeletion`, `goBack`, `deleting`,
  `saving`, `budgetOptions` / `potOptions` ("{label}: {name}" through `menuTriggerName`), `editBudget`,
  `deleteBudget`, `editPot`, `deletePot`, `addNewBudget`, `addNewPot` (the visible "+" is drawn by the button,
  `aria-hidden`). "All themes already have a pot" is `pots.md`'s (H16, T-26).
- **D8. `Button` variants.** `Button` gains `variant` (`primary`, `destroy`, `text`) and `fit` (a width that fits
  its text). Every variant has no hover with `:disabled` or `[aria-disabled="true"]` (H13 (1), (6)); the
  destroy hover is an instant underline, the colour hovers run over `--duration-hover` (UI-2).
- **D9. `ResetBanner` stays as it is.** 2.9 lets the build make it a use of `Notice`; the banner's own dismissal
  storage differs, and changing an Approved page's part is not needed for this task. `Notice` copies its look.
- **D10. Docs in the same pull request:** the backlog row (Done), H13 ticked, `src/ui/README.md`,
  `src/webmcp/README.md`, ADR-0003's dated line for the ids that leave `NOT_YET_BUILT`, the process log and the
  prompts folder with the review brief and its handling.
- **D11. Review.** `/code-review` in a fresh Opus subagent on the diff (governance v1.15); real findings fixed
  before merge.
