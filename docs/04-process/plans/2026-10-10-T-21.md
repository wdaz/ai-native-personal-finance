## Decisions taken in the plan (the spec leaves them to the build)

- **D1. One navigation provider per page, as Transactions.** `BillsNav` is `TransactionsNav` with two parameters
  (`q`, `sort`) and no page: the same intended query, the 250 ms debounce with `router.replace`, a sort by
  `router.push` after a pending search, `popstate` resync, `{ scroll: false }` in `startTransition`. The URL is
  written with a `recurringBillsSearch(query)` helper in `src/shared/recurring-bills-query.ts` (order `q`, `sort`,
  never `latest`).
- **D2. `ResultsRegion` moves with a small shared context.** `src/ui/ResultsRegion.tsx` exports
  `ResultsNavState` (`{ pending, changes }`) as a context; `TransactionsNav` and `BillsNav` each provide it beside
  their own. The component's behaviour and markup do not change; its test moves to
  `tests/unit/ui/ResultsRegion.test.tsx` and Transactions' nav test keeps using it.
- **D3. The layout** (2.13) lives in `app/(app)/recurring-bills/page.module.css`: one column by default;
  `@media (min-width: 768px)` the summary column is a row with both cards `flex: 1`; `@container (min-width:
  961px)` two columns, the summary column 337 px wide and a column again, each card its own height. Below 768 px
  Total Bills lays out as a row, its icon centred beside the label and total.
- **D4. Total Bills' `<wbr>`** (2.6, §18e): `TotalBillsCard` splits the `formatMoney` text at each comma and puts a
  `<wbr>` after it. The Summary's value moves whole with `flex-wrap: wrap` and `margin-left: auto`, as drawn.
- **D5. The copy (H14 (1)).** One new appendix table, "R2 additions … SPEC-recurring-bills, added by T-21", and the
  same entries in `COPY`: `searchBillsPlaceholder`, `searchBillsLabel`, `totalBills`, `billsSummaryTitle`,
  `billsPaid`, `billsTotalUpcoming`, `billsDueSoon`, `billsCountAmount`, `columnBillTitle`, `columnDueDate`,
  `billStatuses` (by `BILL_STATUSES`), `billsStatus` ("{count} bills"), `billsEmpty`, `billsLoadError`. "Monthly -
  {ordinal day}" stays `formatDueDay`'s (T-20); the Amount header reuses `COPY.columnAmount`, the sort labels
  `COPY.transactionSorts`, the no-results text `COPY.billsNoResults`. `BillsCard` (Overview) reads the three labels
  from `COPY`.
- **D6. The tool** (`src/webmcp/tools/recurring-bills.ts`) mirrors `list_transactions`: input `z.object({ search?,
  status?: z.enum(BILL_STATUSES), sort?: z.enum(BILL_SORTS) })`, `GET /api/recurring-bills` with `q` ← `search`,
  output the DTO plus `{ currency: "USD", unit: "cents" }` (2.12), annotations `readOnlyHint` and
  `untrustedContentHint`; `PAGE_TOOLS.recurringBills`; `RecurringBillsTools` in the page's layout.
- **D7. Placeholder tests.** `app-shell.spec.ts`'s `/recurring-bills` row becomes `release2: false`; the WebMCP
  E2E's client navigation from `/recurring-bills` goes to `/pots` (the backlog row). `webmcp.spec.ts`'s placeholder
  checks already use `/pots` (T-19, H11 (4)) and stay.
- **D8. Docs in the same pull request:** the backlog row (Done), H14 ticked, `webmcp-tools.md` §4's pointer row if
  it lists the page's tool as pending, `src/ui/README.md`, `tests/e2e/README.md`, the process log and the prompts
  folder with the review brief and its handling.
- **D9. Review.** `/code-review` in a fresh Opus subagent on the diff (governance v1.15: Copilot review is off for
  `develop`); real findings fixed before merge.
