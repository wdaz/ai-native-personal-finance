with lessons"), as **a document, `docs/04-process/release-1-retrospective.md`** (Q1 (b)), that says what
the specs missed, what the agents got wrong, what the owner changed, and which rules should change; carry
out the rule changes the owner accepts in one pull request (Q3 (b)); then close T-15c so that T-15d
(Release 2 spec work) can open.

  (`roadmap.md`, "Phase 7"; AGENTS.md §3 forbids a later phase's artefacts). The Release 1 document has its
  own name for that reason (Q1).

  and, where it concerns Release 2, as a hand-off to T-15d (Q4).

  This is why the 25 empty "Owner changes" fields need an answer of a different shape (Q2).
