## Decisions taken in the plan (the spec leaves them to the build)

- **D1. Page** (`app/(app)/transactions/page.tsx`, async Server Component): awaits `searchParams`, parses leniently,
  calls `getTransactions(getDb(), query)` directly; on a throw logs `Transactions: getTransactions failed
  requestId=<id>` and renders `TransactionsError` (the Overview pattern). `layout.tsx` renders `children` and
  `<TransactionsTools />`. `page.module.css` holds the card (a size container for TX-1's `@container
  (min-width: 768px)` with a comment naming §25a).
- **D2. `TransactionsNav`** (client provider): the *intended query* in state, reset from the URL on `popstate` and
  when the URL's query changes by a link (`useSearchParams` compared with the last URL it wrote); `setSearch`,
  `setSort`, `setCategory`, `setPage`; `href(query)` writes `q`, `category`, `sort`, `page` in that order with
  `URLSearchParams`, leaving out defaults; `router.replace` for search and `router.push` otherwise, both with
  `{ scroll: false }`, inside `startTransition`; exposes `pending`, and the status line (emptied, then set on the
  next frame). The debounce is `useDebouncedValue(value, 250)` returning the value and a `flush()`, so a menu or page
  change applies a pending search first (2.5), in `src/ui` (it is a React hook; `src/shared` stays React-free).
- **D3. `Menu`** (`src/ui/Menu.tsx` + module): 2.8 exactly — a positioned wrapper (no inline `style`, ADR-0006), the
  trigger with the one `aria-label` "{label}: {current}" (`COPY.menuTriggerName`), a `role="listbox"` panel with
  `aria-activedescendant`, keys, outside click, "one open at a time" through a module-level closer (the
  `TruncatedText` pattern), `aria-disabled` options skipped, the fade under `@media (prefers-reduced-motion:
  no-preference)`. Props: `label`, `options: { value, label, disabled? }[]`, `value`, `onChange`, `icon` (the
  mobile trigger's), `width` as a class (Sort 114 px, Category 177 px from the page's module), `labelVisibility`.
- **D4. `pageItems(current, count, maxNumbers)`** in `src/shared/pagination.ts` (2.1 places it in `src/shared`),
  returning `(number | "gap")[]`; `TransactionsPagination` renders both lists (7 and 3) and CSS hides one per width.
- **D5. The table** (`TransactionTable`, Server Component): 2.9's `<table>` with explicit roles, the hidden caption,
  rows with `TruncatedText` for the name, `formatSignedMoney` and `formatDate`, the empty row (`colSpan={4}`) for
  "No transactions yet" / "No transactions match your search". `ResultsRegion` (client) wraps it with `aria-busy`
  from the nav.
- **D6. Copy (H11 (1)).** The appendix gains an "R2 additions (2026-10-04, owner-approved with SPEC-transactions,
  §9 Q1 and Q4; added by T-19)" table with every string of 2.16 that is not there yet, and the two new places of the
  approved messages (§9 Q4) as rows; `COPY` gains the same keys in the same order, and `copy.test.ts`'s `RENDERED`
  the rows. The ten category names stay data (`CATEGORIES`, the database contract), not `COPY`: the appendix row lists
  them and the test compares that row with `CATEGORIES`.
- **D7. Tokens (H11 (2), (6)–(8)).** `design-tokens.md` gains a "Shadow" heading with `--shadow-popover` and the
  owner's note, `--duration-popover: 150ms` and `--filter-menu-max-height: 360px` in the "App shell"-style table, and
  beige-500's use column becomes "input borders (never text, never under white text)" (the designer's changelog
  §8a); `tokens.css` mirrors them; `scaffold.test.ts` pins the shadow.
- **D8. The tool** (`src/webmcp/tools/transactions.ts`): 2.14's row; input `z.object({ search, category, sort,
  page })` with `z.enum`s and `z.number().int().min(1)`; `apiGet("/api/transactions?…", TransactionsDtoSchema,
  { headers: X-Via })`; `toolSuccess({ ...dto, currency: "USD", unit: "cents" })`. `PAGE_TOOLS.transactions`,
  `TransactionsTools.tsx`, and the registry test's `untrustedContentHint` assertion.
- **D9. Placeholder checks (H11 (4)).** `webmcp.spec.ts`'s client navigation and "polyfill · 0" move to `/pots`;
  a new check on `/transactions` reads "polyfill · 1"; `webmcp-tools.md` §7's E2E row says "Pots" for
  "Transactions" (an amendment of an Approved spec, one sentence, approved by the merge).
- **D10. One pull request**, the one carrying this plan, one commit per task below; the E2E runs locally on
