  the repository's `budgetSpent`, `overviewSummary`, `latestTransactions` and `applyVariant`; none has changed
  since, so 4.2 and 4.4–4.7 move as they are.
- **F2. `applyVariant` sorts ISO text.** `src/server/variants.ts` keeps the latest three by comparing the rows'
  `date` strings; `seedOverviewInput()` holds `Date`s. The domain's version compares instants, which orders the
  seed's fixed-shape ISO text the same way (D2).
- **F3. Labels to enums.** The schemas take the display names (`CategorySchema`, `ThemeSchema`); the database
  takes Prisma's enum values. `CATEGORY_LABEL` and `THEME_LABEL` are built bijections, so the server inverts them
  once (D5) instead of hand-typing a table (T-09 plan D2's reason).
- **F4. A throwing threshold check cannot be caused on the running server.** `write-path.md` 7.2's row needs the
  check to throw after a real route's commit; the API server's environment is fixed. The route's handler is
  called in the test process against the same database with an invalid `RESET_ROW_THRESHOLD` (D7), as
  `write-wrapper.spec.ts` drives `guardedWrite`.
- **F5. 7.3's refusals already run on the budget paths** (`write-refusals.spec.ts`, T-17); with the routes in
  place they now reach real handlers. The "passes the proxy" checks use `/api/pots`; T-23 adds one that a
  same-origin `POST /api/budgets` reaches its handler (a 400 from the schema, not 403, 415 or 404).
- **F6. Three ids leave the shrink-only list.** T-23's tests name US-14, US-18 and US-20 (the backlog row's
  stories), so they leave `NOT_YET_BUILT`: **1 id remains** (US-21, T-25's).

## Decisions taken in the plan (the spec leaves them to the build)

- **D1. Domain** (`src/domain/budgets.ts`, pure, generic over the caller's rows as `overviewSummary` is):
  `latestSpending(category, transactions, count)` = the category's rows through `latestTransactions`;
  `budgetRemaining(maximum, spent)` = `max(0, maximum − spent)`; `budgetsSummary({ budgets, transactions },
  clock)` → `{ items: (B & { spent, remaining, latest })[], spent, limit }` in `seq` order, the totals through
  `sumCents`. `overviewSummary` keeps its own code; a unit test holds the two totals equal for every variant.
- **D2. Variants** (`src/domain/variants.ts`): `SEED_VARIANTS`, `isSeedVariant`, `FEW_TRANSACTIONS` and a
  generic `applyVariant` over `{ transactions: { date: string | Date }[], budgets, pots }`; the latest three by
  instant, the sort stable as before. `src/server/variants.ts` re-exports them, so every caller is unchanged.
- **D3. Shared** (`src/shared/budgets.ts`): `budgetFillPercent(spent, maximum)` in integers (`BigInt`, since
  `spent × 10,000` can pass 2⁵³): basis points rounded half up, capped at 10,000, returned as a percent with at
  most two decimals.
- **D4. Schemas** (`src/shared/schemas.ts`): `BudgetCreateSchema` and `BudgetEditSchema` are one `z.object` of
  `category`, `maximum` (`AmountCentsSchema`) and `theme`, all required (two names, as 2.10 names them);
  `BudgetItemDtoSchema` and `BudgetsDtoSchema` strict, `items` at most ten, `latest` at most three;
  `BudgetWriteDtoSchema = z.strictObject({ budget: BudgetItemDtoSchema })`.
- **D5. Server** (`src/server/budgets.ts`): `getBudgets(db, clock)` reads budgets and transactions (no `where`, the
  Overview pattern), maps them through `categoryLabel`/`themeLabel` and returns `toBudgetsDto(budgetsSummary(…))`;
  `toBudgetItemDto` names every field (no `seq`). The writes are `run` functions for `guardedWrite`:
  `createBudget`, `updateBudget(id)`, `deleteBudget(id)`; each checks `taken` against **other** budgets for
  `category` and `theme` (both reported when both apply) inside the transaction, writes `Budget` only, and the
  create and edit answer `{ budget }` read back through the same summary on the transaction's client (the
  committed state the `GET` would read; 2.10 "computed after the commit … with the same `budgetsSummary`").
  `PRISMA_CATEGORY`/`PRISMA_THEME` invert the label maps (F3).
- **D6. Routes.** `app/api/budgets/route.ts` (`GET`: `no-store`, the 500 logged as 2.11 says; `POST`:
  `guardedWrite` with `BudgetCreateSchema`) and `app/api/budgets/[id]/route.ts` (`PATCH` with `BudgetEditSchema`,
  `DELETE`), each handler calling `guardedWrite` itself (the route-table guard, 7.4); the clock is
  `fixedClock(BUSINESS_TODAY)` and `now` is `new Date()`, read in the route (ADR-0005).
- **D7. Tests.** Unit: the domain row, `budgetFillPercent`, the schemas (every pair of `write-path.md` 2.7's table
  for the three fields), the DTOs strict, `toBudgetItemDto`, the `GET` route's 500 with a throwing database (the
  T-18/T-20 Q2 (a) pattern). API (`tests/api/budgets.spec.ts`): §7's API row against an independent oracle
  (`applyVariant` + the domain); `write-path.md` 7.2's four rows on the real routes (the throwing check by calling
  the route's handler in the test process, F4); one 7.3 "reaches the handler" check (F5).
- **D8. Figures (H15 (2)).** `scripts/seed-figures.ts` gains `budgetFigures()`: 4.2's table cell by cell, the
  totals, the free categories and themes, the new budgets' spent; 4.4's lines; 4.5's variants; 4.6's worked
  writes and 4.7's boundaries, all from `budgetsSummary`, `latestSpending`, `applyVariant` and
  `budgetFillPercent`. `tests/unit/seed-figures.test.ts` holds 4.2's table to the generated one (with one
  violation fixture) and the prose of 4.2 and 4.4–4.7 to generated text.
- **D9. Traceability** (F6): US-14, US-18 and US-20 leave `NOT_YET_BUILT`; ADR-0003's dated line gets one more
  sentence.
- **D10. One pull request**, one commit per task A–D below (the T-18 precedent).
