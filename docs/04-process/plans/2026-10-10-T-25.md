## Decisions taken in the plan (the spec leaves them to the build)

- **D1. Domain** (`src/domain/pots.ts`, pure): `potPercent(total, target)` → basis points, `⌊(2 · total · 10,000 +
  target) / (2 · target)⌋` in `BigInt` (2.3); `potFill` = `min(10,000, potPercent)`; `moneyPreview(pot, kind,
  amount, balance)` with `amount` the cents `parseAmountInput` read, or `null` when the text reads as no amount (it
  moves nothing) — the clamp, the new total, the staying and moving widths and the new percentage of 2.6;
  `isPotNameTaken(name, pots, exceptId?)` trims and compares with `toLowerCase`; `firstFreeTheme(used)` the first of
  `THEMES` not used, or `null` with all fifteen used (PO-Q4 (a)).
- **D2. Shared:** `formatPercent(basisPoints)` in `src/shared/money.ts` ("7.95%", no separator); the schemas in
  `src/shared/schemas.ts`: `PotCreateSchema` and `PotUpdateSchema` are one `z.object` of `name` (`PotNameSchema`),
  `target` (`AmountCentsSchema`) and `theme`, all required; `PotMoneyMoveSchema = z.object({ amount })`;
  `PotDtoSchema` and `PotsDtoSchema` strict, `items` at most 15 (`POTS_MAX`, one per theme);
  `PotWriteDtoSchema = { pot }`, `PotMoneyMoveDtoSchema = { pot, balance: { current } }`.
- **D3. Server** (`src/server/pots.ts`): `getPots(db)` reads the balance and the pots in `seq` order and maps them
  through `toPotDto` (`BigInt` → `Number`, `themeLabel`, `percentBasisPoints`, no `seq`). The writes are `run`
  functions for `guardedWrite`: `createPot`, `updatePot`, `deletePot`, `depositToPot`, `withdrawFromPot`. A name is
  `taken` when another pot's `citext` name equals it (the database compares as the unique index does), a theme when
  another pot holds it; both reported. The edit is a conditional `updateMany` by id (a delete between the read and the
  write is a 404, T-23's review finding).
- **D4. Money** (2.8): a deposit updates the pot first (`total += x WHERE id`; no row → 404, before any business
  rule) and then the balance (`current −= x WHERE current ≥ x`; no row → `exceeds_balance`, and the rollback undoes
  the pot's increment); a withdrawal updates the pot with `WHERE id AND total ≥ x` (no row → re-read: 404 or
  `exceeds_total`) and then adds to the balance. A deletion is `DELETE … RETURNING total` (raw SQL, so the total is
  the deleted row's own, never a value read before) and then `current += total`. Updating the pot first takes its
  row lock, so a deposit and a delete of one pot serialise and the delete returns the deposited total.
- **D5. Routes:** `app/api/pots/route.ts` (`GET`: `no-store`, the 500 of 2.12; `POST`), `app/api/pots/[id]/route.ts`
  (`PATCH`, `DELETE`), `app/api/pots/[id]/deposit/route.ts` and `…/withdraw/route.ts` (`POST`); each write handler
  calls `guardedWrite` itself (7.4's guard). No clock: nothing on Pots depends on the date.
- **D6. Tests.** Unit: the domain row of §7 (4.3's examples, 4.4's ties, failing first), `formatPercent`, the
  schemas' mapper pairs, the strict DTOs, `toPotDto`, the `GET` route's 500 with a throwing database. API
  (`tests/api/pots.spec.ts`): §7's API row against an independent oracle (`applyVariant` + `potPercent`);
  `write-path.md` 7.2 on the pot routes — 4.2's chain conserving 575,600 cents, a deposit and a delete of one pot at
  the same time, two concurrent deposits that together exceed the balance, an id from before a reset, the unique
  constraint as `taken`; US-04 AC2 through `GET /api/overview` (H8); one 7.3 "reaches the handler" check (F4).
- **D7. Figures (H16 (2)).** `scripts/seed-figures.ts` gains `potFigures()`: 4.2's seed pots, the sums and the
  first free theme; 4.3's worked moves; 4.4's edges and ties; 4.5's zero balance and fifteen pots; 4.6's taken
  names — all through `src/domain/pots.ts`. `tests/unit/seed-figures.test.ts` holds §4's prose to generated text.
  4.7 (the card widths), 4.8 (the tool descriptions) and 4.9 (the contrast) are about the page and the tools T-26
  builds, and move with it; H16 (2) is noted done for 4.2–4.6.
- **D8. Traceability** (F5): US-21 leaves `NOT_YET_BUILT`, which is empty; ADR-0003's dated line gets one more
  sentence.
- **D9. One pull request**, one commit per task A–D below (the T-18 precedent).
