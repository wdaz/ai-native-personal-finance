    ## The defect (finding F1 of the T-06 plan, `docs/04-process/plans/2026-09-23-T-06.md` on branch `docs/T-06-plan-gate` — not on main yet, you don't need it)

    T-05 made `middleware.ts` send `Content-Security-Policy: default-src 'self'; script-src 'self' 'nonce-<per-request>'; style-src 'self' 'nonce-<per-request>'; frame-ancestors 'none'` on every response and forward the nonce in the `x-nonce` request header (ADR-0006, amendment 2026-09-23 (2)). Next applies that nonce to its own inline `<script>`/`<style>` tags — but only on pages rendered per request. Evidence from T-05's build output (`.claude/worktrees/T-05-auth/.next/` in the main checkout at `/Users/ruslan/Own/ai-native-personal-finance`): `prerender-manifest.json` lists `/_not-found` as prerendered; `server/app/_not-found.html` has five inline `<script>` tags whose RSC payload says `nonce: "$undefined"`, a `<style>` with no nonce, and inline `style="…"` attributes from Next's default not-found UI (e.g. `style="display:inline-block"`, `style="font-size:14px;font-weight:400;line-height:49px;margin:0"`). The browser blocks all of them, so every 404 — any unknown URL, and `/overview`, `/transactions`, … for a logged-in user until later tasks add those pages — renders unstyled with no client JavaScript. A nonce cannot fix `style` attributes (CSP nonces apply to elements, not attributes); only markup without them can.
