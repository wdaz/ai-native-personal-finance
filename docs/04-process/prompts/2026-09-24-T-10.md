Two real defects were found and fixed before declaring the task done, both described in full in
the process-log entry for this date:

1. A CSS Grid/Flexbox sizing bug (`min-width: auto`'s default letting one fixed-size child —
   the 240 px donut — force every card in its shared column wider than the page), caught by
   re-running the *existing* `app-shell.spec.ts` suite (not just the new file) and finding a
   320 px horizontal-scroll regression; fixed with `minmax(0, 1fr)` and `min-inline-size: 0`.
2. A stale Turbopack build cache (`.next/cache`, accumulated across many incremental
   `npm run build` calls during development) served some components' CSS Module classes with
   no matching stylesheet rule at all — invisible to every automated test (none assert
   background colour), caught only by taking the DoD's own required 1440/768/375 screenshots
   and looking at them; `rm -rf .next` before the next build fixed it, confirmed by re-screenshotting
   and re-running the whole E2E suite against the clean build.

must come from `scripts/seed-figures.ts`'s `seedFigures()`, "never typed" — the first draft of
`overview.spec.ts` had instead typed the dollar figures directly (matching the already-approved,
generated SPEC-overview §4.3 table, a defensible fallback but not what the row asks for). Fixed
by importing `seedFigures()` and formatting through the same `src/shared/money`/`dates`
functions the components themselves use — verified working under Playwright's Node runtime
first with a throwaway import-only test (`tests/api/overview.spec.ts`'s own T-09 note had called
